# Konflux OCE images

Downstream-only Konflux builds of the OpenClaw Enterprise runtime and controller
images on the Hummingbird Node.js 24 runtime and builder streams. Upstream does
not carry these files, so upstream syncs never conflict with them.

| Image          | Dockerfile                                        | Ports                       |
| -------------- | ------------------------------------------------- | --------------------------- |
| oce-runtime    | `deploy/docker/Dockerfile.konflux.oce-runtime`    | `deploy/runtime/Dockerfile` |
| oce-controller | `deploy/docker/Dockerfile.konflux.oce-controller` | `Dockerfile` (runtime)      |

Both images build from this repository as their context. They moved here from
the [agentic base images](https://gitlab.com/redhat/rhel-ai/core/base-images/agentic)
repository (RHAI-16354), which built them from a pinned commit of this fork.

## Layout

- `deploy/docker/Dockerfile.konflux.<image>`: the Hummingbird ports.
- `deploy/konflux/<image>/build-args.conf`: build arguments for the Konflux
  `build-args-file` parameter. The PipelineRuns must also pass `OCE_COMMIT`,
  the source revision (`OCE_COMMIT={{revision}}` in `build-args`), for the
  image labels and the console build stamp.
- `deploy/konflux/<image>/smoke-test.sh`: image checks, using `common.sh`.
- `deploy/konflux/oce_pins.py`: derives the runtime pins and detects recipe
  drift (see below). `test_oce_pins.py` holds its unit tests.
- `.github/renovate.json`: extends the org MintMaker default, which only
  bumps digests in Konflux Dockerfiles. Automerge stays off for these images
  until a Konflux build gates the updates.

The Konflux PipelineRuns in `.tekton/` are generated by automation rather than
kept here by hand.

## Build locally

```sh
deploy/konflux/build-local.sh oce-controller   # about a minute
deploy/konflux/build-local.sh oce-runtime      # about 45 minutes
```

The script builds with podman as the PipelineRuns do, then runs the smoke test.

## Upstream syncs

The Dockerfiles are hand ports, so an upstream sync that changes
`deploy/runtime/Dockerfile` or the root `Dockerfile` must carry the port. With
full git history, from the repository root:

```sh
python3 deploy/konflux/oce_pins.py            # refresh the derived pins
python3 deploy/konflux/oce_pins.py --check    # list stale pins and the recipe diff
```

`--check` masks pin values, bridge patch checksums, comments and whitespace,
then diffs each upstream recipe against the commit recorded in that image's
`OCE_REVIEWED_COMMIT`. For the controller it skips the `development` stage,
which the port does not carry. Port what the diff shows, then record the port:

```sh
python3 deploy/konflux/oce_pins.py --ported runtime
python3 deploy/konflux/oce_pins.py --ported controller
```

`--ported` also stores a fingerprint of the port in `OCE_PORT_SHA256`, and
refuses when the port has not changed since. If an upstream change needs no
port, set `OCE_REVIEWED_COMMIT` by hand and say why in the pull request.
`--check` fails when a port changes without `--ported`, when the two ports pin
different base images, and when a downloaded artifact no longer matches its
checksum.

The `Konflux OCE Pins` workflow runs the same check on pull requests and on
pushes to main.

## Status

The builds are not hermetic yet (`hermetic: "false"`): they download pnpm, the
OpenClaw source, tini, gh, matrix-sdk-crypto and the dependency trees during
the build. Hermetic builds need RPM lockfiles, a Hermeto generic lockfile for
the tarballs, and prefetchable OCE and OpenClaw dependency closures.
